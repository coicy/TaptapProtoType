## 一、游戏概述

### 1.1 核心体验陈述

在这个游戏里，玩家感受到：自己只调整几处摊位和规则，整个小镇市场却会因为顾客偏好、摊主选择和空间拥堵自行形成新的秩序。

### 1.2 基本信息

| 项目 | 内容 |
|------|------|
| 游戏名称 | 《涌市》 |
| 开发团队 | 2–5 人小团队；首个切片按个人四小时原型约束执行 |
| 游戏类型 | 3D 模拟经营 / 空间布局 / 涌现式系统游戏 |
| 美术风格 | 明亮的低多边形小镇，暖色木材、彩色遮阳棚、清晰的功能色 |
| 目标平台 | PC 浏览器；后续可评估桌面端 |
| 游戏引擎 | Three.js + TypeScript + Vite；适合快速验证空间关系、射线交互和轻量 NPC 模拟 |
| 目标玩家画像 | 喜欢布局、观察系统变化和轻度优化的泛用户，主要为 18–34 岁，愿意进行 10–30 分钟的重复实验 |
| 内容分级/边界 | 全年龄；不含暴力、赌博、性化内容和现实政治表达 |
| 商业模式 | 原型阶段不设商业化；正式版倾向买断制或一次性 Demo 转正式版 |
| 游戏规模 | 一个可反复实验的小镇市场；正式版 3–5 个主题市场、20–30 种摊位规则 |
| 开发周期 | 首个四小时原型；可玩 Demo 4–6 周；完整小型作品 4–6 个月 |
| 核心特色 | 以局部规则产生全局市场结构；玩家观察并引导涌现，而不是直接管理每个 NPC |

### 1.3 游戏简介

玩家接手一块正在复兴的小镇广场，负责决定摊位放在哪里、给谁留出通道、哪些商品在早市出现。顾客拥有简单但相互影响的需求、预算、耐心和同行关系；摊主会根据销量调价、补货或迁移。每天开始后，玩家只能观察市场如何自行运行，并在下一天调整布局。目标不是找到唯一最优解，而是让市场在有限空间与有限库存下形成稳定、可解释、能持续赚钱的生态。

### 1.4 目标玩家画像

| 维度 | 结论 | 对设计的影响 |
|------|------|--------------|
| 受众取向 | 泛用户、轻策略、模拟经营爱好者 | 首屏直接展示会移动的顾客和可点击摊位；避免复杂面板开局 |
| 年龄层 | 18–34 岁为主，全年龄可理解 | 用图标、颜色和短句表达需求，数值保持少而清楚 |
| 核心动机 | 创造/布局、观察发现、轻度优化、收集变化 | 玩家可以暂停、回放结果并比较“为什么这一天不同” |
| 游玩频率 | 每次 10–30 分钟；可碎片化重开 | 一天市场控制在 90 秒左右，失败后立即重置 |
| 内容边界 | 温和、明亮、无暴力；允许市场失败但不惩罚性羞辱 | 失败结果使用“客流转移”“库存浪费”等中性反馈 |

### 1.5 参考游戏

| 参考方向 | 借鉴的设计模式 | 《涌市》的转化 |
|----------|----------------|----------------|
| 《Mini Metro》 | 少量规则、持续增长的网络压力、清晰的颜色反馈 | 将线路压力换成摊位吸引力、步行距离和排队压力 |
| 《Mini Motorways》 | 玩家设计基础设施，城市行为自行演化 | 玩家布置市场空间，不直接操控顾客路线 |
| 《Townscaper》 | 通过简单摆放产生整体结构和视觉反馈 | 保留“摆放即创作”的低门槛，但加入可解释的经营结果 |
| 轻量店铺模拟游戏 | 资源进货、价格和客流的经营闭环 | 缩小数值管理，突出局部规则如何形成群体结果 |

以上仅借鉴设计模式，不复制其 IP、角色、剧情或美术资产。

### 1.6 市场竞品分析

| 竞品 | 可借鉴点 | 我们的差异化 | 需要避免的问题 |
|------|----------|--------------|----------------|
| 《Mini Metro》 | 一眼可读的系统图、逐步增加的压力 | 市场对象有个性和需求链，结果可以通过空间布局解释 | 规则数量过多导致玩家只看告警，不再观察系统 |
| 《Mini Motorways》 | 建设动作简单、城市流动持续变化 | 不依赖道路绘制，把“拥堵”转化为排队、串联消费和摊主迁移 | 纯效率解题会压低实验和审美空间 |
| 《Townscaper》 | 快速摆放、低失败压力、整体反馈即时 | 交易结果与 NPC 行为让摆放具有长期后果 | 若只剩装饰，会失去经营目标 |
| 传统农场/餐厅模拟 | 明确资源产出和升级目标 | 资源不是固定配方，而是由顾客群体和摊位关系共同决定 | 过度扩张到背包、任务、员工等生产系统 |

### 1.7 一句话卖点

**“摆下一个摊位，观察一整座市场如何改变。”**

## 二、核心玩法设计

### 2.1 核心循环

```text
观察昨日市场报告
    ↓
选择 1 个摊位 / 位置 / 价格策略
    ↓
开始 90 秒市场日
    ↓
顾客按局部规则移动、排队、购买、串联消费
    ↓
摊主根据销量和库存调整行为，市场结构出现偏移
    ↓
结算收入、满意度、浪费和涌现事件
    ↓
带着新假设进入下一天，或重置重做
```

玩家的核心动作是“布局并观察”。模拟运行时玩家不能逐个命令 NPC，避免把系统退化成传统的单位微操。

### 2.2 玩法深度

**上手门槛：** 先放置面包摊和饮品摊，点击“开市”，通过颜色和排队长度理解结果。  
**中期策略：** 在有限格子中权衡高流量位置、摊位互补、通道宽度和库存风险。  
**长期目标：** 让不同类型的市场生态稳定出现，例如“早市快买”“午后闲逛”“高价精品街”，并收集其形成条件。  
**策略边界：** 玩家每个市场日最多进行 2 次布局调整，保证每次调整都可归因，减少无意义试错。

### 2.3 主要系统

| 系统 | 最小规则 | 对核心体验的贡献 |
|------|----------|------------------|
| 摊位布局 | 网格占位、入口距离、相邻加成、通道宽度 | 玩家用空间改变群体行为 |
| 顾客代理 | 需求、预算、耐心、距离、已购买商品 | 产生分流、排队和连带消费 |
| 摊主代理 | 库存、价格、补货阈值、迁移倾向 | 让供给对需求做出局部响应 |
| 市场时间 | 早高峰、平峰、收摊三个阶段 | 同一布局在不同时间出现不同结果 |
| 反馈报告 | 客流图、交易链、拥堵点、异常事件 | 让不可预期的结果可解释、可复盘 |
| 市场声誉 | 一天级别的满意度和复访率 | 提供轻量的长期目标，不引入复杂任务树 |

### 2.4 操作方式

| 操作 | 输入 | 反馈 |
|------|------|------|
| 旋转/平移观察 | 鼠标拖拽、滚轮；键盘 WASD 可选 | 相机平滑移动，网格高亮 |
| 选择摊位 | 鼠标点击/射线检测 | 显示类型、库存、价格和最近客流 |
| 放置/移动摊位 | 选中摊位后点击合法网格 | 幽灵预览显示占位与入口距离 |
| 调整单价 | 摊位面板的 +/- 按钮，原型只允许低/中/高三档 | 价格变化实时更新预计吸引力 |
| 开市/暂停 | 空格键或 UI 按钮 | 时间轴、事件提示和暂停状态 |
| 重置市场 | R 键或 UI 按钮 | 清除本日变化，恢复初始布局 |

## 三、系统详细设计

### 3.1 空间布局系统

市场使用 9×7 的地面网格，入口位于南侧，摊位占用 1–2 个格子。玩家每一天开始时拥有 3 个基础摊位：面包、饮品、手工艺。

布局影响由以下规则组成：

1. **距离：** 顾客对目标的效用每格减少 0.08；超过 12 格通常会放弃。
2. **入口视野：** 摊位与入口之间无遮挡时获得 +15% 初始曝光。
3. **邻近互补：** 面包与饮品相邻时，完成第一笔购买的顾客有 35% 概率继续购买另一类商品。
4. **排队压力：** 每名等待顾客使摊位服务时间增加 0.4 秒；超过耐心值则离队。
5. **通道拥堵：** 同一格同时经过 3 名以上顾客时，移动速度下降 20%，形成可见的拥堵热点。

这些规则必须在 UI 中可见或可通过报告推断，不能依靠隐藏的“神秘加成”。

### 3.2 顾客代理系统

每位顾客由 5 个核心字段驱动：

| 字段 | 原型范围 | 作用 |
|------|----------|------|
| 需求标签 | 面包、饮品、手工艺中的 1–2 个 | 决定可接受摊位集合 |
| 预算 | 4–12 金币 | 价格超过预算则跳过 |
| 耐心 | 4–12 秒 | 决定排队是否离开 |
| 逛街倾向 | 0–1 | 高值顾客更愿意尝试相邻摊位 |
| 复访倾向 | 0–1 | 影响下一天开市人数 |

每 0.25 秒重新评估一次目标，但只有在当前目标失效、排队过长或顾客完成购买时才切换，避免 NPC 抖动。

目标评分示意：

```text
目标分 = 需求匹配 × 0.45
       + 预算可接受 × 0.20
       + 距离便利 × 0.20
       + 摊位声誉 × 0.10
       + 逛街倾向带来的尝试加成 × 0.05
```

顾客完成一次交易后，若满足连带消费条件，会把相邻互补摊位加入候选；若失败，则在报告中记录“价格过高”“等待过久”或“走得太远”。

### 3.3 摊主与供给系统

摊位不需要单独操控员工。每个摊位拥有库存、售价、基础服务时间和声誉。

- 开市前按固定补货量补充库存，原型不做进货路线。
- 当库存低于 30% 时，摊主在下一天自动减少曝光，模拟谨慎经营。
- 当连续两天销量低于 20% 时，摊位声誉下降；连续两天销量高于 80% 时，声誉上升。
- 正式版可加入摊主迁移，但首个原型只用“下一天建议迁移”的报告提示，避免引入复杂动画和寻路。

### 3.4 市场时间与节奏

每个市场日 90 秒：

| 阶段 | 时长 | 行为特点 |
|------|------|----------|
| 早高峰 | 0–25 秒 | 需求集中，距离和入口视野影响最大 |
| 平峰 | 25–70 秒 | 逛街倾向和连带消费开始显现 |
| 收摊 | 70–90 秒 | 耐心下降，剩余库存和拥堵决定最后收益 |

市场日结束后展示 5 秒结算报告，玩家可暂停在报告页查看“客流从入口到摊位的路径”。

### 3.5 涌现事件与可解释反馈

“涌现”不是随机事件表，而是多个局部规则达到阈值后的命名与可视化。首批事件如下：

| 事件名称 | 触发条件 | 玩家看到的反馈 |
|----------|----------|----------------|
| 早餐潮 | 早高峰面包交易占比 ≥ 55%，入口距离低 | 一条明显的黄色客流带，报告显示“早餐潮” |
| 饮品尾流 | 面包交易后 35% 以上顾客转向饮品 | 两个摊位之间出现蓝色连线和连带收益 |
| 热点拥堵 | 某格平均同时人数 ≥ 3，持续 5 秒 | 地面变红，顾客速度下降，报告标记拥堵点 |
| 精品孤岛 | 手工艺价格高但仍有稳定客群 | 摊位周围显示低流量、高客单价图标 |
| 价格逃逸 | 某类售价超过预算中位数 1.4 倍 | 顾客绕行或离场，报告给出“价格过高” |

每个事件必须显示“触发原因”，并至少给出一个玩家可尝试的反事实建议，例如“把饮品移到面包旁边，观察尾流是否增强”。

### 3.6 胜负与重置

首个原型使用软胜负，避免玩家被一次错误布局卡死：

- **达成：** 3 天累计净收入 ≥ 60 金币，且平均满意度 ≥ 65%。
- **暂时失败：** 某天满意度低于 35%，显示“市场冷清”，仍可调整后继续。
- **重置：** 随时恢复到当天开市前；结算后可一键重新布局。
- **完整 Demo 目标：** 收集 3 个不同涌现事件，解锁“市场观察者”徽章。

## 四、数值设计框架

### 4.1 核心数值体系

| 数值 | 初始值 | 来源 | 消耗/影响 |
|------|--------|------|-----------|
| 金币 | 30 | 每笔交易收入 | 调整价格不直接消耗；正式版用于扩建 |
| 库存 | 每摊 18 件 | 每日固定补货 | 每次购买消耗 1 件，剩余库存形成浪费评分 |
| 顾客数 | 每日 12 人 | 满意度和复访倾向决定下一日 ±2 | 顾客离场会降低收入与满意度 |
| 满意度 | 60% | 购买成功、等待时间、价格公平 | 连续低满意度减少复访 |
| 声誉 | 0–100 | 稳定供货和满意交易 | 影响目标评分和涌现事件 |

单笔收入：

```text
收入 = 售价 × 购买数量
净收入 = 总收入 - 库存浪费罚分 - 拥堵罚分
```

原型只使用低、中、高三档价格：售价分别为 2、3、5 金币；服务时间分别为 1.4、1.8、2.4 秒。数值集中放在配置对象中，便于快速调参。

### 4.2 成长曲线

首个 Demo 不做传统等级和科技树，成长体现在玩家掌握规则与收集事件。

- 第 1 天：3 个摊位、低价、顾客少，教学距离和排队。
- 第 2 天：允许一次价格调整，复访顾客增加，验证连带消费。
- 第 3 天：增加 1 个障碍格或入口变化，验证玩家能否迁移策略。
- 正式版：通过事件图鉴解锁新摊位规则，而不是单纯提高数值。

### 4.3 核心指标定义

| 指标 | 目标值/观察方式 | 设计含义 |
|------|------------------|----------|
| 首次开市完成率 | ≥ 90% 的测试者能在 2 分钟内完成一次开市 | 反馈是否足够清楚 |
| 垂直切片完成率 | ≥ 70% 测试者能完成 3 天市场 | 核心循环是否可理解 |
| 平均单次会话时长 | 10–20 分钟 | 是否有继续实验的动力 |
| 首次涌现发现时间 | 5 分钟内看到至少 1 个命名事件 | 主题是否可感知 |
| 反事实实验率 | ≥ 50% 测试者会重置并改变布局 | 玩家是否把游戏当作系统实验 |
| 规则解释正确率 | 访谈中 ≥ 70% 能说出事件的一个原因 | 涌现是否可解释 |
| 反馈质量 | 试玩后至少 3 条关于布局/客流的具体反馈 | 为后续数值调参收集证据 |

## 五、美术需求清单

### 5.1 角色美术

- 原型：低多边形胶囊身体 + 颜色区分需求标签，不制作骨骼动画。
- 顾客颜色：黄色=面包、蓝色=饮品、紫色=手工艺；混合需求使用双色标记。
- 摊主使用静态小人或摊位旗帜，重点是远处可识别性。

### 5.2 场景美术

- 9×7 网格地面、南侧入口、少量树和长椅障碍。
- 3 种基础摊位：面包车、饮品棚、手工艺桌；采用几何体和纯色材质。
- 客流用半透明色带或小箭头显示，拥堵格使用脉冲色块。
- 不引入外部模型、复杂灯光、后处理或音频资源到四小时切片。

### 5.3 UI 设计

- 左上：当天、金币、满意度、库存浪费。
- 右侧：选中摊位的价格三档、库存条、最近 5 秒客流。
- 底部：开市/暂停、重置、结算报告按钮。
- 结算报告：收入、满意度、涌现事件和一条因果解释；避免堆叠长文本。

### 5.4 特效音效

- 原型只做 CSS/Three.js 视觉反馈：交易闪光、排队圆环、事件提示。
- 后续再加入环境底噪、交易铃声和拥堵音量变化。

## 六、技术架构建议

### 6.1 推荐引擎

使用 Three.js + TypeScript + Vite。项目已有 3D 原型定位，原生 Three.js 足以完成网格场景、正交相机、射线拾取和轻量 NPC 移动；不引入 React、物理引擎、联网、存档或复杂资源管线。

### 6.2 核心技术点

1. **数据与表现分离：** `MarketState` 保存摊位、顾客和时间；Three.js 对象只负责表现。
2. **固定模拟步长：** 以 0.25 秒更新代理决策，渲染帧只插值位置，保证结果可复现。
3. **空间查询：** 网格坐标保存占位、通道和拥堵计数；不依赖对象名称或层级顺序。
4. **轻量寻路：** 原型使用网格上的 BFS 生成入口到摊位的短路径；正式版再评估更复杂寻路。
5. **事件检测器：** 每秒从交易、客流和排队统计中计算阈值，输出 `EmergenceEvent`，UI 与报告共用。
6. **可复现随机：** 每个市场日使用可记录的 seed，重置后能复现同一批顾客，便于比较布局差异。
7. **配置集中管理：** 价格、速度、耐心、阈值放入 `simulationConfig`，不散落在脚本中。

推荐模块边界：

```text
src/
  simulation/      MarketState, CustomerAgent, StallAgent, rules
  spatial/         Grid, pathfinding, occupancy
  presentation/    scene, camera, meshes, feedback
  ui/               hud, stall-panel, day-report
  config/           simulationConfig
```

## 七、MVP 与垂直切片

### 7.1 MVP 范围

| 模块 | 必须包含 | 暂缓/不做 | 验证目的 |
|------|----------|-----------|----------|
| 核心玩法 | 1 个市场、放置/移动摊位、开市、顾客购买、结算、重置 | 多市场、员工管理、手动进货 | 验证布局是否能改变客流与收入 |
| 内容 | 3 种摊位、12 名顾客、3 天流程、至少 3 个涌现事件 | 任务树、升级树、复杂摊主性格 | 验证局部规则是否产生可观察差异 |
| 美术 | 几何体、颜色、简单 HTML/CSS UI、客流与拥堵可视化 | 外部模型、角色动画、后处理、音频 | 验证空间关系和反馈可读性 |
| 技术 | Three.js 场景、正交相机、射线点击、固定步长模拟、seed 重置 | React、物理引擎、联网、存档 | 验证技术路径能否在浏览器稳定运行 |

### 7.2 垂直切片

玩家进入一个带南侧入口的低多边形广场，看到 3 个已放置摊位和 12 名带颜色标签的顾客。第一次开市无需解释面板，玩家观察顾客因距离和价格分流。结算页指出一个明确事件，例如“饮品尾流：面包顾客中有 41% 继续购买饮品”。玩家移动饮品摊到面包摊旁边或把它移到入口附近，再开市比较两次结果。完成第 3 天后，玩家看到累计收入、满意度、发现过的事件和“下一步可以测试”的布局建议。整个片段目标时长 10–15 分钟。

### 7.3 核心假设

| 假设 | 验证方式 | 通过标准 |
|------|----------|----------|
| 玩家能理解“空间布局会改变客流” | 首次试玩观察 + 口头复述 | 70% 以上玩家能主动指出一个距离或相邻关系 |
| 简单局部规则能产生玩家认为有意义的涌现 | 记录事件发现、重置和布局变化 | 每位玩家平均发现 ≥ 1 个事件，并至少重做 1 次布局 |
| 事件解释能把意外结果转化为下一次实验 | 结算页 A/B 测试：有/无原因解释 | 有解释组的下一日布局调整率提高 ≥ 20% |
| 90 秒市场日不会让玩家觉得等待 | 试玩问卷与行为日志 | 80% 以上玩家愿意开完第二天市场 |
| 3D 低成本表现足以支撑空间判断 | 目标窗口截图与观察测试 | 无关键摊位遮挡，客流和拥堵在 3 秒内可读 |

## 八、开发里程碑

### Phase 1：四小时核心玩法验证

- **目标：** 跑通“放置 → 开市 → 顾客移动/购买 → 结算 → 重置”。
- **交付物：** 一个 `index.html` 可启动场景、3 种几何摊位、12 个顾客、HUD、重置按钮。
- **验证指标：** 连续运行 10 次无运行时错误；移动一个摊位后客流统计发生可解释变化。

### Phase 2：系统完善（第 1 周）

- **目标：** 加入价格三档、库存、排队压力、客流带和 3 个涌现事件。
- **交付物：** 日结算报告、seed 重放、配置集中管理、基础测试记录。
- **验证指标：** 5 名外部试玩者中至少 4 人能说出一次布局改变结果的原因。

### Phase 3：垂直切片（第 2–4 周）

- **目标：** 完整 3 天流程、障碍格、事件图鉴、低多边形风格统一。
- **交付物：** 10–15 分钟可分享 Demo，包含首次引导和结束画面。
- **验证指标：** 垂直切片完成率 ≥ 70%，首次涌现发现时间 ≤ 5 分钟。

### Phase 4：内容与打磨（第 2–4 个月）

- **目标：** 增加 3–5 个市场主题和可复用规则组合，完善音效、相机和可读性。
- **交付物：** 20–30 分钟可重复体验的小型完整版本。
- **验证指标：** 每个主题至少支持两种稳定生态；内容生产速度不低于每周 1 个可玩主题。

## 九、风险评估

### 9.1 技术风险

| 风险 | 影响 | 应对 |
|------|------|------|
| NPC 路径交叉造成抖动或穿模 | 顾客行为不可信 | 原型限制单层网格，使用占用格和目标锁定；必要时降低顾客密度 |
| 涌现结果不可复现 | 玩家无法比较实验 | 固定步长、seed 和事件阈值日志；重置复现同一顾客样本 |
| 3D 视角导致遮挡 | 无法判断布局 | 采用正交相机、固定俯视角、摊位高度上限和鼠标悬停高亮 |
| 代理数量增长导致性能下降 | 运行不稳定 | 原型上限 40 个顾客；避免每帧分配，按 0.25 秒批量更新决策 |

### 9.2 市场风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 玩家把游戏理解成纯装饰摆放 | 经营目标不成立 | 首日明确显示收入、满意度和事件因果；让摊位移动有即时结果 |
| 玩家认为结果只是随机 | 涌现主题失效 | 每个事件给出至少一个可操作原因，保持随机只改变顾客个体而非规则 |
| 与传统经营模拟相比内容显得少 | 长期留存不足 | 用事件图鉴和不同生态作为收集目标，暂不堆叠任务与建筑数量 |

### 9.3 生产风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 2–5 人团队在 3D 美术上超支 | 延期 | 先使用低多边形和程序几何；模型只替换表现层，不改变模拟接口 |
| 规则迭代缺少数据 | 数值反复推倒 | 每次试玩记录布局、开市结果、事件、重置和玩家解释；以假设表驱动迭代 |
| 扩展功能稀释核心主题 | 原型失焦 | 新功能必须回答“是否直接验证涌现或市场布局”；否则进入后续清单 |
